# Modula Workflow Requirements — harvested from live trio runs

Status: living · started 2026-07-23 · owner: lead

Each entry is a **product requirement for Stack Modula's agent-workflow engine**, derived
from a friction or fix we hit while dogfooding the Lead/Coder/Verifier trio. Provenance is
mandatory — every requirement names the run that taught it, so the product team can trace a
feature back to its evidence. This is the bridge from "our process" (see
[`operating-model.md`](./operating-model.md)) to "Modula's feature list."

Graduates into a formal Modula "Agent Workflow Engine" FRD once F4 (#283) lands.

Three findings define the run's lesson, and they are all the same lesson: **a check that cannot fail protects nothing.** (1) CP-3's diff overlays lost `position: absolute` and computed to `static` — every focused test passed because the assertions only checked the SELECTORS EXISTED. (2) The Lead dock covered the Coder pane entirely at 900px — invisible in a diff; only exercising the state found it. (3) The replacement browser gate was FAIL-OPEN, converting genuine geometry regressions into skips; it was deleted rather than shipped, because no gate beats a green light that cannot turn red. Every subsequent fix on this run was required to carry an assertion that demonstrably fails on reintroduction.

Two structural findings worth carrying forward. **Specced surfaces may not exist:** CP-2's premise was largely wrong — jobs-mode switch, context menu, gauges, renew chip and PR/FRD chips were all absent from the app, not merely unstyled, so "reskin" was impossible and the operator re-scoped mid-run. Verifying that a surface EXISTS before planning to restyle it is now a standing pre-checkpoint step. **Advisory findings need triage, not forwarding:** Kody was right twice and wrong twice, and even when right its suggested patch was not behavior-identical (it proposed a pair-emptiness predicate where restoring the original `hasPeerWorkspace` was the faithful fix). Blind-forwarding would have shipped a second regression while fixing the first.

Operator eyes remain irreplaceable (MW-15): the human spotted two real defects — a page-bot panel overlaying the pane toolbar, and red-dominant job cards — that no agent surfaced, because the verifier measures geometry and asserts invariants but cannot judge whether a page READS wrong. The red turned out to be native emoji glyphs ignoring CSS tokens entirely; the tokens were already correct, so token-repainting would have "fixed" nothing.

**Opus-5-as-lead A/B (prd-293 / PL2, 2026-07-24→25) — operator trial vs the Fable-led #286 run.** Recorded by the lead itself, so read the self-assessment with that bias in mind; the checkable claims are cited.

*Where lead judgment measurably changed the outcome.* (a) **Verification over acceptance** — three coder claims were checked rather than believed: "9 environmental node failures" was actually 7 with no regression (a flat pass-count with rising failures is a regression signature, so the label mattered); `executionSlotCount` reuse was confirmed against `adminConfig.ts:39,161` + `slot_queues.py:12` before ratifying; and the CP-1 critical fix was validated by reverting the `if not committed` guard and watching `test_post_commit_lock_release_failure_reports_success` fail. (b) **Severity re-rating in both directions** — CP-1 F002 downgraded HIGH→LOW and pushed out of scope after reading `conversation_lock.py` and finding the empty-token lock self-heals via the existing reaper (pre-existing shared-module defect, cross-consumer blast radius); CP-2 S1-004 upgraded HIGH→CRITICAL because the verifier's own text said "Stage 1 is nonfunctional" — a broken feature, not a defect in a working one. (c) **Non-convergence diagnosed rather than iterated** — at 11→10 open the lead stopped ratifying and supplied three structural designs (hash the received bytes instead of re-serializing across languages; per-project claim instead of a global lock; generation token validated at the side-effect boundary instead of another check), on the read that the coder was applying local patches to structural problems. (d) **Two correct predictions** — that a relocated capacity recheck would move rather than close the TOCTOU window (confirmed by the verifier the next round), and that a post-`os.replace` fallible op would break byte-identical-on-failure.

*Where the lead was wrong — both times on the same instinct.* It twice applied "reuse before inventing" to the **wrong target**: prescribing `conversation_lock.py` for a claim path that lives in async TypeScript (Python-only, unimportable, and a spawned holder would release at subprocess exit), and prescribing a lock at all without first asking whether more than one process writes the store — the answer was single-writer, so the correct fix was no lock. The coder caught both. Lesson for the operating model: **a lead's design authority must be paired with an explicit "tell me if this is wrong" channel, and pushback must be treated as signal**; both errors cost minutes because the coder stopped instead of building a fourth failed variant.

*Process cost, which dominated everything else.* Roughly 5.5h elapsed produced CP-1 complete + committed (`b86418b`) and CP-2 stage 1 ~90% through fix round 2 — but the lead spent a large share of its cycles on transport pathology, not engineering: an unanswered one-line ACK head-of-line-blocked the hub for ~40 min (MW-27) while three real reports sat invisible behind it; the coder stalled **five times**, each triggered by emitting a message (MW-24); and detection was hand-rolled `/proc` CPU sampling because no work-signal exists (MW-10/MW-26). The single highest-leverage product fix this run argues for is not better lead reasoning — it is **auto-ack + auto-continue at the transport layer**, which would have removed nearly all of the above.

| MW-24 | **Acknowledgement must be a transport primitive, not an agent action.** The ack-then-work protocol (MW-14's mitigation for the single outbound slot) is self-defeating on a turn-based runtime: the agent replies "ack", the reply ENDS ITS TURN, and it goes idle having done none of the work it just acknowledged. The platform must auto-ack a delivered directive at the transport layer — freeing the sender's slot on delivery, not on the recipient's reply — and immediately re-drive the recipient with the directive body so receipt never consumes the recipient's turn. ## Proposed solution — Continuation Supervisor (addresses MW-9 / MW-10)

The concrete fix for turn-based agents that stop mid-task. Modula's orchestrator runs a
**continuation supervisor** per active agent — which is exactly what the lead is prototyping by
hand in this run:

- **Monitor by work-signal** (MW-10): sample CPU delta, live subprocesses, and working-tree/turn
  changes — never the coms heartbeat.
- **Re-drive on idle-while-incomplete**: when an agent's work-signal falls to zero but the task is
  not complete (no completion report, no `needs_lead` blocker), auto-issue a re-drive.
- **Targeted, not generic**: the re-drive names the exact next step (fix these findings / run the
  gates / send the handoff / review the re-submit) — directive nudges advance work where a bare
  "continue" often does not.
- **Every role**: coder, verifier, and any other agent — all are turn-based and stall.
- **Terminate cleanly**: stop re-driving on task-complete or a genuine blocker (surface to lead);
  after N consecutive re-drives with zero progress, escalate to the human (truly wedged).

Net: what the lead does manually here — poll, detect the stall by work-signal, send a targeted
re-drive — becomes an automated orchestrator loop in the product.
